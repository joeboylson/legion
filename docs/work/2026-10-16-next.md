Picked up from the LEGION-DEV session. Missions to add to `dev` first thing.

## 1. Landing a mission must not freeze legiond (urgent)

Seen 2026-10-15 at about 15:10 and 17:35: every `legion` command, the app
and every session's tools got "Connection refused" while legiond landed a
mission. A sample of the live legiond showed `handle_command` →
`mission_commands` → `git::finish_mission_branch` →
`git::replay_onto_moved_base` running the folder's check (`cargo test`, minutes
long) while holding the daemon's state lock; every other request
(`take_deliveries`, `opencode_session_ids`, `report_setup_changes`) waited on
that lock until the socket's queue filled.

Rules: run the check (and any other long git or shell step in a finish)
without holding the state lock. Take what the finish needs under the lock,
release it, run the check, then take the lock again to record the outcome,
re-checking that the mission and base haven't changed meanwhile. Done when a
test runs a slow check (a sleep) during a finish while other commands still
answer within a second.

  temp_plus_platform/v2-q4 reaches about 49% context within 5 minutes from

  task-builders fill most of their context before writing anything, because
